Rebuilding the Global Search Index

The search index is a JSON file that lists every file in all four archive sections. It must be rebuilt manually after new files are added to any archive section. Run time is approximately 5–15 minutes depending on total file count.

⚠️ The SAS token in the script expires August 31, 2026. After that date, generate a new SAS token and update the $SAS variable in the script. Also update $AzCopy if AzCopy moves to a new location.

Steps to rebuild the index

  1. Download Build-ArchiveSearchIndex.ps1 from the Downloads section above and save to C:\Temp\
  2. Make sure AzCopy is accessible — the script uses C:\Users\mlund\Downloads\azcopy.exe by default. Update the $AzCopy variable in the script if yours is in a different location.
  3. Open PowerShell as Administrator
  4. Allow the script to run and execute it:
# Allow script execution for this session, then run
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass
C:\Temp\Build-ArchiveSearchIndex.ps1
  1. The script scans all four archive sections and shows progress per section — expect 90–120 minutes for 556,000+ files
  2. When complete it uploads four separate index files plus a master index to Azure automatically:
    search-index-ProdShared.json, search-index-Share.json, search-index-PS-Archive.json, search-index-AH-Archive.json, search-index-master.json
  3. Users will see updated search results within 10 minutes (API cache TTL)
ℹ️ The portal still works for folder browsing while the index is rebuilding. Only global search is temporarily unavailable.

Uploading New Files to the Archive

⚠️ Always use \* at the end of the source path to copy contents rather than the folder itself. This prevents nesting issues (e.g. ProdShared\ProdShared\).

AzCopy upload — single folder

# Template — replace SOURCE_PATH and DEST_FOLDER
$SAS = "?sv=2026-02-06&ss=bfqt&srt=co&sp=rwdlacupiytfx&se=2026-08-31T23:51:41Z&st=2026-08-19T15:59:10Z&spr=https&sig=lk7OQyxeGTSjbevHEL5UdyDEiJlgoJuXBs6kgibZJxg%3D"

C:\Tools\AzCopy\azcopy.exe copy "D:\SOURCE_PATH\*" `
  "https://usuoarchive.blob.core.windows.net/usuo-archive/DEST_FOLDER$SAS" `
  --recursive --check-length --log-level INFO

AzCopy upload — department Archive_Years folders (loop)

# Loops through all department folders, uploads Archive_Years as Archive
$SAS        = "?sv=2026-02-06&..."  # paste full SAS token
$AzCopy     = "C:\Tools\AzCopy\azcopy.exe"
$SourceRoot = "D:\Data\PSDepShare"   # or AHDepShare
$DestRoot   = "https://usuoarchive.blob.core.windows.net/usuo-archive/PS-Archive"

Get-ChildItem -Path $SourceRoot -Directory | ForEach-Object {
    $arch = Join-Path $_.FullName "Archive_Years"
    if (Test-Path $arch) {
        & $AzCopy copy "$arch\*" "$DestRoot/$($_.Name)/Archive$SAS" --recursive
    }
}

After uploading — always rebuild the search index

  1. Verify the upload in Azure Portal → Storage browser → usuo-archive → confirm folder structure looks correct with no nesting
  2. Run Build-ArchiveSearchIndex.ps1 to include new files in search results
  3. Test the portal at archive.myusuo.org — search for a file you just uploaded to confirm it appears

Adding a user to the archive

  1. Go to entra.microsoft.com → Groups → USUO-Archive-Readers
  2. Click Members → + Add members → search for the user → Select
  3. Access takes effect within 5 minutes — no portal restart needed

Managing restricted folder access (HR folders)

Two PS-Archive folders are restricted to specific staff only — PS-Archive/HR and PS-Archive/HR Share. Access is controlled via two Entra ID security groups. Add or remove members to grant or revoke access instantly — no code changes needed.

FolderEntra ID GroupGroup ID

PS-Archive/HR ShareUSUO-Archive-HR-Share0cb2df7f-33db-49bb-bf9d-f6bbeb65ce9e

To ADD a user to an HR folder:

  1. Go to entra.microsoft.com → Groups → search for USUO-Archive-HR or USUO-Archive-HR-Share
  2. Click the group → Members → + Add members
  3. Search for the user by name or email → Select → Add
  4. Access takes effect within 5 minutes — no deployment or restart needed

To REMOVE a user from an HR folder:

  1. Go to entra.microsoft.com → Groups → find the group
  2. Click Members → check the box next to the user's name
  3. Click Remove at the top → confirm
  4. Access is revoked within 5 minutes
ℹ️ Users NOT in these groups will not see the HR or HR Share folders at all when browsing PS-Archive — the folders are completely hidden, not just blocked.
⚠️ To add a new restricted folder pair, update the RESTRICTED_FOLDERS object in api/checkaccess/index.js and the matching array in public/index.html, then deploy via GitHub.

Renewing the SAS token

  1. Azure Portal → Storage accounts → usuoarchive → Shared access signature
  2. Set permissions: Blob only, Container + Object, Read/Write/List/Add/Create, new expiry date
  3. Generate SAS → copy the SAS token
  4. Azure Portal → Static Web Apps → usuo-archive-browser → Environment variables → update AZURE_STORAGE_SAS
  5. Update $SAS in Build-ArchiveSearchIndex.ps1 and any upload scripts
